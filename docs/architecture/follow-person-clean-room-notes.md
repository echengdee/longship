# FollowPerson V0 independent-implementation notes

This change was authored for Longship from behavioral requirements and public
interfaces. No source file, code fragment, comment block, shell script,
configuration file, test fixture, HTML page, or directory tree was copied from
the reference implementation.

The behavioral requirements retained for interoperability were: one atomic
RGB-D scene, short-lived person IDs, base-local obstacle-aware following,
bounded last-seen recovery, nearby-position reacquisition, an independent raw
forward-clearance stop path, read-only diagnostics, deterministic simulation,
an optional MuJoCo physics target, and explicit physical deployment gates.

The Longship implementation was designed around this repository's existing
contracts/Runtime/target-adapter boundaries. It introduces its own names,
contracts, state representation, planner, governor, mock world, dashboards,
CLI, tests, simulator target, and deployment workflow. The MuJoCo plugin uses a
new planar proxy model generated by Longship and does not reuse a reference
model, simulator bridge, scene, or policy. Features unrelated to FollowPerson
on the reference branch—such as carton handling, box carry, dialogue
integration, and policy handoff—were intentionally excluded.

The later system-simulation addition independently composes Longship's existing
voice-event boundary with a new bounded Follow Brain proposal and Mission
Runtime. It tests semantic Skill admission and protected STOP without importing
the reference intent router, Brain gateway, harness, or deployment scripts.

The interactive stack was implemented as another provider for Longship's
existing `RuntimeTextPort`, not by importing the reference stack supervisor or
terminal. The optional Codex Follow provider reuses Longship's own SDK session
boundary and introduces a new Follow-only output schema.

The timed interaction addition implements the first executable subset of
Longship's own documented `TaskDraft -> MissionTaskGraph -> Runtime` design.
The bounded Follow draft, linear-DAG compiler, monotonic node scheduler,
cancellation epoch, HUD graph snapshot, and tests were authored from the
Longship architecture contracts. No reference scheduler, task representation,
timer, prompt, terminal implementation, or dashboard code was reused.

The external G1 seam contains no robot asset or policy bytes. Reference files
were inspected only to establish observable interface facts and then bound by
content and license hashes. Longship independently validates the external
bundle and deliberately refuses to call asset loadability a locomotion pass.
The later dynamic G1 plugin independently implements the Longship target/world
boundary around the externally installed Unitree RL Gym tensor and MJCF
contracts. It does not import the reference runtime, launcher, controller
source, or configuration. The full asset directory, policy, configuration,
and license remain external and are required to match reviewed hashes.

After Longship added provider-neutral artifact and policy contracts, the
dynamic target was refactored to consume those Longship-owned interfaces. The
new manifest contains identities and external references only; the 47-value
observation adapter, verified TorchScript loader, lease/version candidate
construction, and guard integration were independently authored in this
repository. No 29-DoF upstream adapter or training implementation was
transplanted into the 12-DoF target.

As a final mechanical check, all independently authored Python and shell lines
and other text/configuration lines of at least 80 characters were searched
verbatim across both the behavioral reference changes and the locally
inspected Unitree simulator/provider source. After the task-graph addition, a
broader UTF-8 scan of every one of the 91 changed/untracked candidate files
against 25,387 files in the locally supplied reference repository found zero
exact whitespace-normalized line matches at 80 characters or longer.
Generated, cache, environment, Git, build, and files larger than 5 MB were
excluded. This is a narrow copying check, not a substitute for source review or
legal advice.

This note records engineering provenance; it is not a legal opinion or a claim
of hardware qualification.
